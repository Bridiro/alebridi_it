1.1

Steering wheel firmware

E-Agle Trento Racing Team · 2024 – now

The firmware behind the driver's display and controls on the team's Formula Student car.

I joined the software department in December 2024 to work on the steering wheel: the display, the buttons and rotary encoders, the LED rows, all talking to the rest of the car over CAN. After contributing to the wheel firmware for Fenice Evo, I'm bringing up the next one from an empty project on a dual-core STM32H747.

The display runs from a framebuffer in external SDRAM, filled with DMA2D and scanned out by the LTDC controller. The rest of the board is configured by hand: timers for LED and backlight PWM, a DAC for the buzzer, ADC channels for temperature sensors, an SD card through FatFs. Static analysis runs clang-tidy against the SEI CERT rules, with every warning treated as an error.

1.2

libraster

Embedded UI library · C · 2025 – now

A screen described as a flat list of boxes, drawn with one primitive the platform provides.

libraster asks the platform for exactly one thing: a way to fill a rectangle. On the steering wheel that callback goes to DMA2D; on a desktop it's SDL_FillRect; on a raw framebuffer it's two nested loops. Swapping hardware never touches library code.

It never allocates. In partial mode only boxes flagged as updated are redrawn, so a frame where one value changes costs one box, not one screen. Fonts are generated from TTF files into C sources at build time, each with its own glyph lookup the compiler can fold into a jump table.

1.3

glyphr

Font rasterizer · Rust, no_std · 2025 – now

Text rendering for microcontrollers that aims to be one of the best-looking, not the fastest.

glyphr grew out of the font work in libraster. A proc macro turns a TTF into signed distance fields, scalable at runtime, or into packed 1-bit bitmaps when memory matters more. At runtime there is no heap and no framebuffer of its own: you pass a callback that writes one pixel, or one that receives a whole glyph tile for a DMA2D blit.

Every glyphr-rendered pixel on this page, from the name at the top to the playground beside this text, comes from the published crate compiled to WebAssembly. The module, with 95 glyphs baked in, is about 98 KB.

1.4

tuican

CAN bench tool · Rust · 2026

Everything needed on the bench to talk to a CAN bus, in one binary.

Pick an adapter, load a DBC, edit signals by name and send them once or periodically, while a live table decodes what comes back. Rules let it react: when a received signal matches, it sends a message on its own, which is enough to stand in for a node that isn't on the bench yet.

It works with SocketCAN, gs_usb/candleLight and serial adapters, and ships as prebuilt binaries for macOS, Linux and Raspberry Pi. The Pi builds are cross-compiled with cargo-zigbuild and need nothing installed beyond libc.

1.5

phantomata

Type-state state machines · Rust, no_std · 2026

State machines where an illegal transition is a compile error, not a bug report.

Each state is a zero-sized marker type and the machine's current state lives in its type, so a transition written for Locked cannot run on Unlocked. A target state with no handler, typos included, fails to type-check. The whole table is one define_fsm! block.

It is no_std friendly, and an async variant lets transitions await I/O on any executor: a channel, a queue or an interrupt-backed FIFO.

From an outline to a lit pixel

Most of my work sits somewhere on this path. Each stage below is drawn by the code it describes.

  1. a

    Outline

    Quadratic curves from a TrueType file. Nothing a microcontroller wants to evaluate per frame.

  2. b

    Distance field

    Baked at compile time into flash: each texel stores how far it is from the edge. glyphr, libraster

  3. c

    Coverage

    Sampled at any size and smoothed across the edge into an 8-bit alpha per pixel. glyphr

  4. d

    Layout

    Boxes and labels. Only what changed is redrawn. libraster

  5. e

    Panel

    DMA2D fills the framebuffer, LTDC scans it out to the display. Steering wheel
